  note: background IoU (0.3586 on 124 crops) is STRUCTURAL, not a comparable failure - a crop is the union of the unit's OWN boxes, so background is only the thin leftover corners and gaps, a small region where IoU is naturally harsh. It is not evidence against the model.
  note: cartridge (127 instances) and bay (43 instances) crop populations are OVERLAPPING on this validation split, measured fresh this run (not assumed): 84 crops carry cartridge only, 0 carry bay only, 43 carry BOTH in the SAME crop, 0 carry neither. See seg_dataset.py's module docstring for why this can no longer be assumed disjoint (real tray-wall geometry, commits 27cbd97..9fcf136). Either way, 0.9293 and 0.8873 are each pooled independently over their own class's pixels across the whole split - a marginal per-class statistic, not a per-crop joint one - so this is still not evidence the model handles both together within the SAME crop, even on crops where both truly co-occur.
  note: checkpoint selection is noise-limited - best.pt 0.7323 and last.pt 0.7309 differ by 0.0013 on 43/35/29 (bay/electronics/obstruction) val instances, and both ship.

  head mm = 4.68 px x that class's own mean mm/px. The 4.68 x 10.29 px comes from a 28x28 head over a PowerCore26800 crop of ~131 x 288 px (FDR 13.2.1), which is 2.9 x 6.4 mm at the generator's NOMINAL 0.6250 mm/px - the figure the FDR published, and the framing no frame in this corpus was rendered at.
  Both sides of this comparison are pixel counts times the same scale, so the `clears by` ratio is SCALE-INVARIANT: correcting the calibration moves the millimetres and leaves the architecture verdict exactly where it was.
  verdict: BELOW the mask-head quantisation figure - supports the architecture choice.
